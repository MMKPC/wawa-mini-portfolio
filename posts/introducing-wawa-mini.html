Why WAWA Mini?

A local search project with a practical studio question: how do you find a useful note when you no longer remember its wording?

By Matthew Mitchell · October 23, 2026 · MMKPC Studios

In this postThe problemThe foundationCurrent scopeWhat comes next

A design note can be useful long after the words used to describe it have changed. WAWA Mini is my exploration of that retrieval problem.

The studio problem

Development produces notes about mechanics, systems, and decisions. Searching across those documents becomes difficult when a question uses different language from the original note. A literal match is useful when the wording is known; semantic retrieval offers another way to rank potentially relevant passages.

My goal is to make that difference visible and measurable. The intended studio use is finding source material that can support ongoing work, with enough context to inspect where each result came from.

Continuing an existing foundation

WAWA Mini began in COS550 and continues as my COS660 graduate capstone. The capstone builds on the existing Python project rather than starting a separate product. The current increment adds persistent cross-document retrieval and an evaluation that compares explicit keyword conditions with local semantic search.

SQLite FTS5 supplies the keyword index. Ollama runs the embedding model locally, and the application stores a semantic snapshot for later searches. Results are ranked original passages with source references. This keeps the work centered on retrieval behavior and software reliability.

A focused, inspectable tool

The implemented interface is a command-line application. Indexing and rebuilding are manual. It supports keyword and semantic retrieval; generated answers, a graphical interface, and automatic document watching are future possibilities.

Local retrieval, clear limits. The software runs its retrieval workflow locally. The current pilot uses synthetic notes and relevance labels without independent human validation, so its results describe that fixture rather than real studio-wide effectiveness.

What this journal will track

This portfolio records implemented features, technical decisions, evidence, and limitations. The immediate direction is to examine performance, strengthen evaluation, and keep the claims proportionate to what the software actually demonstrates.

The first October engineering retrospective explains the retrieval paths, the strongest baseline, and why the pilot’s results do not establish a general winner.
